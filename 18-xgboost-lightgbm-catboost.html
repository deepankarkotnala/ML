1 · From the ground up

🧩
In plain words

These three libraries all run the gradient boosting loop from the previous module. None of them invented a new kind of model. What they each did was fix a different practical failing of the textbook algorithm: XGBoost put tree complexity into the objective so the maths itself controls overfitting, LightGBM attacked the cost of finding a split so it scales to millions of rows, and CatBoost fixed a subtle target leak that everyone else's categorical handling suffers from. Knowing which problem each one solves is the whole module.

Start with the problem, not the formula

Plain gradient boosting from the last module works, and has three concrete weaknesses that show up the moment you use it on real data.

  • Nothing in the objective mentions tree size or leaf values. Complexity is controlled from outside, by max_depth and friends, rather than being something the optimiser trades off.
  • To find the best split, you sort each feature and scan every possible threshold. That is O(rows × features) per node, and it dominates training time on large data.
  • Categorical features must be encoded by hand. The most effective encoding — replace each category with the mean target for that category — leaks the answer into the features.
So what: these three weaknesses map one-to-one onto the three libraries. If you can name the weakness, you can derive why each library exists rather than memorising a feature list.

XGBoost: put complexity in the objective

XGBoost writes down what it is actually minimising, complexity included:

Obj = Σᵢ L(yᵢ, Fᵢ) + Σₜ Ω(fₜ)  where  Ω(f) = γT + ½λ Σⱼ wⱼ²

T is the number of leaves and wⱼ is the value a leaf predicts. So γ charges rent per leaf, and λ is an L2 penalty on how large a leaf's output may be. Pruning is no longer an afterthought — a split that does not earn more than γ is rejected by the objective.

So what: "regularised boosting" is not marketing. Complexity moved inside the thing being optimised, which is the difference between XGBoost and the classical GBM it replaced.

The second-order trick, and where the famous formula comes from

The loss is awkward to optimise directly, so XGBoost approximates it. Expand L to second order in the new tree's contribution, using gᵢ for the first derivative (the gradient) and hᵢ for the second (the Hessian). Drop constants and the objective for a single leaf j collapses to

Gⱼwⱼ + ½(Hⱼ + λ)wⱼ²  where  Gⱼ = Σ gᵢ, Hⱼ = Σ hᵢ over the rows in that leaf.

That is just a parabola in wⱼ. Set the derivative to zero — Gⱼ + (Hⱼ + λ)wⱼ = 0 — and you get the optimal leaf value and the objective it achieves:

wⱼ* = − Gⱼ / (Hⱼ + λ)  and  Obj* = − ½ · Gⱼ² / (Hⱼ + λ)

So what: being able to produce w* = −G/(H+λ) and say where it came from — set the derivative of a parabola to zero, exactly as in Module 06's normal equation — is one of the highest-value 90 seconds in a boosting interview. The split gain follows immediately: ½[G_L²/(H_L+λ) + G_R²/(H_R+λ) − G²/(H+λ)] − γ, which is "score of the two children minus score of the parent, minus the rent on the new leaf".

Raising λ steepens the parabola, which drags the minimum toward w = 0 and makes the best achievable objective less negative. Both effects are the regularisation: leaves predict smaller values, and splits have to work harder to justify themselves. Note that H sits in the denominator alongside λ — a leaf backed by few or low-curvature rows is shrunk automatically, which is why min_child_weight is a constraint on H, not on a plain row count.

LightGBM: stop scanning every value, and grow greedily

LightGBM leaves the objective alone and attacks the cost per split, with four ideas.

  • Histogram binning. Bucket each continuous feature into ~255 bins once, up front. Split search then scans 255 candidates instead of every distinct value — a large constant-factor win, and the bins are reused at every node.
  • Leaf-wise growth. Rather than completing each depth before descending, always split whichever leaf anywhere in the tree promises the largest gain. Same number of leaves, much lower loss — and much deeper, lopsided trees.
  • GOSS (Gradient-based One-Side Sampling). Rows with large gradients are the ones still being got wrong, so keep all of those and randomly subsample the small-gradient rows, upweighting the survivors to keep the estimate unbiased.
  • EFB (Exclusive Feature Bundling). In sparse one-hot data many features are never non-zero together, so bundle them into a single feature. Fewer effective features to scan.
So what: leaf-wise growth is the trade to remember. It reaches a lower training loss for the same number of leaves, and it overfits small datasets much more readily — which is why num_leaves is LightGBM's critical knob and why max_depth alone will not save you. On a few thousand rows, prefer XGBoost or cap num_leaves hard.
Level-wise fills each depth; leaf-wise chases the best gain

Both trees have four leaves, so both cost the same to store and evaluate — but the right-hand one spent its budget where the loss was largest instead of spreading it evenly. That is strictly better on large data and strictly more dangerous on small data, which is the entire practical difference between the two libraries' defaults.

CatBoost: the leak nobody notices

Target encoding replaces a category with the mean target for that category. It is powerful and it is leaky: the mean for "London" includes the row you are about to predict, so the feature already contains a piece of that row's answer. Training loss drops beautifully and validation does not follow.

CatBoost's fix is ordered target statistics. Impose a random permutation on the rows and encode each row using only the target values of rows that came before it. No row can ever see its own label, and averaging over several permutations keeps the variance down.

It then applies the same reasoning to boosting itself. In standard boosting, the residual for row i is computed from a model that was trained on row i — a mild but systematic bias called prediction shift. Ordered boosting maintains models trained on prefixes of the permutation, so a row's pseudo-residual always comes from a model that never saw it.

So what: CatBoost's headline is "handles categoricals natively", but the substance is leak-free handling. If a panel asks why target encoding needs care, the answer is this leak and the ordered fix — not "use one-hot instead".

Choosing between them, honestly

On tabular data with sensible tuning, all three land within noise of each other far more often than the benchmarks suggest. The real selection criteria are practical:

  • Many high-cardinality categoricals → CatBoost, for the encoding alone. Strong defaults, so it often wins with little tuning.
  • Large data, training time matters → LightGBM, and budget your attention for num_leaves.
  • Small or medium data, want predictable behaviour → XGBoost, whose level-wise growth is harder to blow up.
So what: the answer that scores is "they are the same algorithm with different engineering, so I choose on data shape and tuning budget, not on a leaderboard". Claiming one is simply the most accurate is the trap.

3 · Core intuitions

XGBoost’s central idea: regularization belongs in the objective

Standard gradient boosting fits a tree to the pseudo-residuals and then, separately, applies heuristics like depth limits. XGBoost writes down a single objective including tree complexity, where T is the number of leaves and w_j the leaf weights, then solves for the optimal tree under that objective. So leaf count and leaf magnitude are penalized by construction, and split decisions already account for complexity cost.

The second-order expansion is what makes it work

Approximate the loss around the current prediction with a second-order Taylor expansion using gᵢ = ∂L/∂ŷᵢ and hᵢ = ∂²L/∂ŷᵢ². Because the resulting objective is quadratic in the leaf weights, you can solve it in closed form. For a leaf with sample set I_j, writing G_j = Σgᵢ and H_j = Σhᵢ, the optimal weight is w_j* = −G_j/(H_j + λ) and the quantity G²/(H+λ) is XGBoost’s “similarity score”.

Three things fall out of that one formula, and pointing them out is the mark of a strong answer:

  1. λ in the denominator shrinks leaf weights, most strongly for leaves with small H — few or low-confidence samples, which is exactly where you want shrinkage.
  2. γ is subtracted from the gain, so a split is only made if its gain exceeds γ — principled pre-pruning built into the split criterion.
  3. Using the Hessian rather than sample counts means “how much data is in this leaf” is measured in confidence-weighted information — which is what min_child_weight actually thresholds on, a subtlety most candidates miss.

Missing values get a learned direction

At each split, XGBoost sends all missing values to the left child, computes the gain, then sends them all right and computes the gain, and keeps whichever is better as that split’s default direction. So missingness handling is learned per split from the data rather than imputed by a global rule. That is a genuine advantage on messy tabular data and a common interview question.

LightGBM grows leaf-wise: faster, and more prone to overfitting

XGBoost’s classic level-wise growth expands all nodes at a given depth before going deeper, producing balanced trees. LightGBM instead picks the single leaf with the highest split gain anywhere in the tree and splits that. For the same number of leaves this reaches lower loss, because it spends capacity where it pays most — but it produces deep, unbalanced trees that can carve out very specific regions, so it overfits small datasets more readily. Consequently num_leaves (not max_depth) is the primary capacity knob, and it is important that num_leaves stays well below 2^max_depth or the depth constraint does nothing.

GOSS and EFB are what make LightGBM fast

GOSS exploits the observation that samples with small gradients are already well-fitted and contribute little to further split-gain estimation, so it keeps all large-gradient samples and randomly subsamples the small-gradient ones, reweighting to keep the gain estimate unbiased — fewer samples per iteration, nearly the same split decisions. EFB exploits sparsity: in one-hot-encoded or otherwise sparse data, many features are almost never non-zero simultaneously, so they can be bundled into a single feature without losing information, reducing the effective feature count substantially.

CatBoost’s ordered boosting fixes a subtle bias

In conventional gradient boosting, the residual for sample i is computed using a model that was itself trained on sample i. That is a mild form of target leakage, and it produces a systematic prediction shift — the distribution of residuals seen during training differs from what you would see on unseen data, biasing the fit.

CatBoost’s ordered boosting fixes it using random permutations: the residual for a sample is computed from a model trained only on samples appearing before it in the permutation. The same principle powers its ordered target statistics for categorical features — the target encoding for a row uses only preceding rows, which is a principled solution to the target-encoding leakage problem from Module 04. That is why CatBoost is often strongest on categorical-heavy data with little tuning.

Oblivious trees

CatBoost uses symmetric trees where every node at a given depth splits on the same feature and threshold. That is a strong structural constraint — hence a regularizer, which helps on smaller data — and it makes inference extremely fast, since a prediction becomes a bit-vector index lookup rather than a branchy traversal. Worth knowing as a real differentiator when serving latency matters.

Where all three still lose, in 2026

They cannot extrapolate beyond the training range, so trending targets need detrending or explicit trend features. They handle genuinely multimodal data (text + image + tabular) only if you convert the other modalities into features first. They need enough data — on a few hundred rows a regularized linear model often wins. And they are not naturally calibrated, so add Platt or isotonic calibration if you need honest probabilities.

On what is new: tabular foundation models — in-context learners such as the TabPFN line — emerged as a credible approach for small tabular datasets and are worth knowing about, but gradient-boosted trees remain the default baseline to beat on medium-to-large tabular problems. The defensible interview position is to name the newer approaches while treating GBDTs as the benchmark.

7 · Hands-on drill

  1. Compute the XGBoost gain formula by hand for a small toy split with λ = 1 and γ = 0. Then set γ = 2 and confirm the split is rejected. This exercise makes γ and λ concrete.
  2. Train XGBoost, LightGBM and CatBoost on the same tabular dataset with defaults, then after tuning. Record accuracy and wall-clock training time for all six runs.
  3. Insert missing values deliberately and confirm all three train without imputation. Compare their scores against an explicitly-imputed pipeline.
  4. Take a dataset with several high-cardinality categoricals. Compare one-hot + XGBoost, out-of-fold target encoding + XGBoost, LightGBM native categorical, and CatBoost defaults. CatBoost usually wins with the least effort — get that result in your own notebook.
  5. Demonstrate LightGBM’s leaf-wise overfitting: train with num_leaves = 255 on a small dataset and watch the validation gap open. Then constrain num_leaves and min_child_samples.
  6. Fit with eval_set and early stopping; plot the validation curve and note the selected iteration.
  7. Plot a calibration curve for tuned XGBoost, then apply isotonic regression on a held-out set and re-plot.

Gotchas that fail candidates
  • Not knowing XGBoost uses the second derivative. This is the distinguishing feature.
  • Saying min_child_weight is a row count. It is the sum of Hessians.
  • Setting num_leaves above 2^max_depth in LightGBM, so the depth limit does nothing.
  • Not knowing what makes LightGBM fast — GOSS, EFB, histogram binning, leaf-wise growth.

8 · Interview questions

6 questions
01What does XGBoost add over standard gradient boosting?XGBoostsecond orderregularized objective＋
Strong answer

Four categories.

(1) A regularized objective. Instead of fitting a tree to pseudo-residuals and controlling complexity with external heuristics, XGBoost writes the objective as loss plus γT + ½λΣw_j², penalizing both the number of leaves and the magnitude of leaf weights, then solves for the optimal tree under that objective.

(2) A second-order approximation. It Taylor-expands the loss to second order using the gradient gᵢ and Hessian hᵢ, making the per-leaf problem quadratic and therefore closed-form: the optimal leaf weight is w_j* = −G_j/(H_j + λ) and the split gain is ½[G_L²/(H_L+λ) + G_R²/(H_R+λ) − (G_L+G_R)²/(H_L+H_R+λ)] − γ. Using curvature rather than just slope gives better leaf values per iteration and faster convergence — it is Newton’s method in function space rather than plain gradient descent. Notice also that γ being subtracted makes pre-pruning part of the split criterion itself, and that min_child_weight thresholds the sum of Hessians, so leaf size is measured in confidence-weighted information rather than raw row counts.

(3) Sparsity-aware split finding. Missing values get a learned default direction per split, chosen by trying both and keeping the higher gain.

(4) Systems engineering. The weighted quantile sketch gives approximate split finding on data too large to sort exhaustively; histogram binning, a compressed column-block layout, cache-aware access and out-of-core computation are what make it fast in practice.

30-second version

A regularized objective with γT + ½λΣw², a second-order Taylor expansion giving closed-form leaf weights w* = −G/(H+λ), sparsity-aware learned missing directions, and heavy systems engineering.

What’s being tested

Depth on the most important tabular algorithm. The second-order point is essential; the γ and min_child_weight observations mark a top-band answer.

02Derive XGBoost’s optimal leaf weight.derivationleaf weightmath＋
Strong answer

After the second-order expansion, the objective for a single tree is Σᵢ[gᵢf(xᵢ) + ½hᵢf(xᵢ)²] + γT + ½λΣ_j w_j². Since f is constant w_j on each leaf, group the sum by leaf: for leaf j with sample set I_j, its contribution is G_j w_j + ½(H_j + λ)w_j², where G_j = Σgᵢ and H_j = Σhᵢ.

That is a one-dimensional quadratic in w_j, convex because H_j + λ > 0. Differentiate and set to zero: G_j + (H_j + λ)w_j = 0, so w_j* = −G_j/(H_j + λ).

Substituting back gives the leaf’s optimal contribution −½G_j²/(H_j + λ), and summing over leaves gives −½Σ_j G_j²/(H_j+λ) + γT. The split gain is then the improvement in that quantity when a leaf is divided, minus γ.

Two readings of the result: λ shrinks the leaf weight, hardest when H_j is small — leaves with few or low-confidence samples, exactly where shrinkage is wanted; and G²/(H+λ) is the “similarity score” the popular explanations refer to.

30-second version

Group the second-order objective by leaf to get G·w + ½(H+λ)w², a convex 1-D quadratic. Differentiate and set to zero: w* = −G/(H+λ), giving optimal contribution −½G²/(H+λ).

What’s being tested

Genuine mathematical fluency on the algorithm you claim to use daily. Very few candidates can do this, which makes it a strong differentiator.

03XGBoost vs LightGBM vs CatBoost. How do you choose?comparisonGOSSordered boosting＋
Strong answer

They share the gradient-boosting core and differ in growth strategy and engineering.

XGBoost grows level-wise (with histogram-based splitting now the default), is the most mature and best-documented, and is a safe default.

LightGBM grows leaf-wise — always splitting the leaf with highest gain anywhere in the tree — which reaches lower loss for a given number of leaves but produces deep unbalanced trees that overfit small datasets more readily. Combined with GOSS (subsampling small-gradient rows while keeping all large-gradient ones) and EFB (bundling mutually-exclusive sparse features), it is typically fastest on large data, and num_leaves rather than max_depth is its main capacity knob.

CatBoost uses ordered boosting and ordered target statistics to eliminate the prediction shift and target-encoding leakage affecting standard boosting, plus oblivious (symmetric) trees that act as a strong regularizer and make inference very fast.

Choosing: CatBoost when the data is categorical-heavy or high-cardinality, or when I have little tuning time — its defaults are the strongest of the three; LightGBM when the dataset is large and training speed matters; XGBoost as the well-understood default, especially where ecosystem maturity matters. In practice I would fit all three with defaults early — it costs minutes — and tune whichever leads.

30-second version

XGBoost is level-wise and mature; LightGBM is leaf-wise with GOSS and EFB, fastest but overfits small data; CatBoost uses ordered boosting and symmetric trees, best on categoricals with least tuning. Fit all three with defaults, tune the leader.

What’s being tested

Whether you know the actual algorithmic differences rather than brand preferences. Naming GOSS, EFB, leaf-wise growth, ordered boosting and oblivious trees correctly is the bar.

04How does XGBoost handle missing values?missing valuessparsity-aware＋
Strong answer

It learns a default direction per split. When evaluating a candidate split, it computes the gain with all missing-valued rows sent to the left child, and again with them all sent to the right, and stores whichever direction produced the higher gain as that split’s default. At prediction time a missing value follows the stored default.

This is genuinely different from imputation: the handling is learned from the data, it can differ across splits — so missingness can mean different things in different regions of the feature space — and it implicitly exploits informative missingness, since if absence is predictive the learned direction captures that automatically. It is also efficient, because the algorithm only iterates over non-missing values when enumerating split points, which is why the technique is called sparsity-aware split finding.

Caveat worth adding: this handles missingness for the model, but it does not tell you why values are missing, so I would still investigate the mechanism and consider adding explicit missing-indicator features if the pattern seems meaningful.

30-second version

It learns a default direction per split — trying all-missing-left and all-missing-right and keeping the higher gain. Learned from data, can differ per split, and exploits informative missingness.

What’s being tested

A very common question with a specific answer. “It handles them automatically” is not enough — the interviewer wants the learned-default-direction mechanism.

05Walk me through tuning XGBoost on a new dataset.tuningworkflowearly stopping＋
Strong answer

In a fixed order, cheapest-signal first.

  1. Establish the validation strategy first — stratified K-fold, or time-based if there is temporal structure — because tuning against a leaky split is worse than not tuning.
  2. Fit defaults with learning_rate = 0.1, a high n_estimators, and early stopping. That one run tells me the achievable ballpark and how many trees the problem wants.
  3. Tune capacity: max_depth (3–10) and min_child_weight (1–20) — the biggest lever after the learning rate.
  4. Tune sampling: subsample and colsample_bytree in 0.6–1.0, which regularize and decorrelate.
  5. Tune explicit regularization: reg_lambda, gamma, and reg_alpha if I want sparser leaves.
  6. For the final model, drop the learning rate to 0.01–0.03, raise n_estimators correspondingly, and re-run early stopping.
  7. If the target is imbalanced, set scale_pos_weight = n_neg/n_pos and tune the decision threshold separately on validation.

For the search itself I would use random search or a Bayesian optimizer such as Optuna rather than exhaustive grid search, since the parameters interact and grid search wastes most of its budget. And I would hold a final untouched test set to measure once at the end, because tuning on the validation folds makes the validation score optimistically biased.

30-second version

Validation strategy first, then defaults with early stopping, then capacity, then sampling, then regularization — finally lower the learning rate for the production model. Random search or Optuna, not grid search, and one untouched test set.

06Would you use a neural network instead of XGBoost on tabular data in 2026?appliedjudgmenttabulartrap＋
Strong answer

Usually not, and I would want a specific reason to. On medium-to-large tabular data, gradient-boosted trees remain the strongest default: axis-aligned splits match how tabular features actually behave, they handle mixed types and missing values natively, they need no scaling, they train in minutes, and they typically match or beat neural approaches while requiring far less tuning — a finding that has held up across repeated benchmark studies.

I would consider a neural approach when: the problem is genuinely multimodal (tabular plus text or images), where a network can learn a joint representation end to end; there are very high-cardinality categoricals where learned embeddings capture structure that encoding schemes lose; I want transfer learning from a pretrained model; the target is highly structured (sequences, graphs); or I need a single end-to-end differentiable system for a downstream task.

It is also worth naming what is new: tabular foundation models — in-context learners of the TabPFN family — became a credible option for small tabular datasets, and using LLM-derived embeddings of free-text columns as features inside a GBDT is now a standard and very effective hybrid.

My practical position is that GBDTs are the baseline any alternative must beat, and I would require a measured win on a properly designed validation split before choosing anything more complex.

30-second version

Usually not — GBDTs match tabular structure, need no scaling, and win with less tuning. Go neural for multimodal inputs, very high-cardinality categoricals needing embeddings, or transfer learning. And the strongest hybrid is text embeddings as features inside a GBDT.
